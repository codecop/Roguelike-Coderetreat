# PHPUnit Testing Instructions for Laravel & PHP

These instructions guide the creation of high-quality, maintainable unit tests that follow modern testing practices and Laravel conventions.

## 1️⃣ General Guidelines

- Always write unit tests that are small, focused, and deterministic
- Name test methods clearly, reflecting what is being tested and under what conditions
- Example: `it_returns_correct_sum_when_inputs_are_positive` or `test_addition_returns_correct_sum_when_inputs_are_positive`
- Follow **Arrange–Act–Assert (AAA)** pattern:
  - **Arrange**: Setup test data and mocks
  - **Act**: Execute the function/method under test
  - **Assert**: Check results
- Avoid unnecessary dependencies; use mocks/fakes/stubs when testing in isolation
- Keep one assertion per behavior where possible. Multiple assertions are allowed if they test the same behavior
- Include edge cases and error cases, not just happy paths

## 2️⃣ Naming Conventions

- **Class names**: `ClassNameTest`
- **Method names**: `it_[condition]_[expectedOutcome]`
- **Variable names**: Descriptive and meaningful
- Avoid abbreviations unless widely understood

## 2️⃣.1️⃣ Property Declarations & Class Structure

### **Flexible Property Declarations:**
You can use either PHPDoc annotations OR typed properties based on your project's PHP version and requirements:

**PHPDoc Style (PHP 7.4+ compatible):**
```php
/** @var \SpOTTCommon\Media\Media */
private $media;

/** @var \SpOTTCommon\Media\MediaRepositoryInterface|Mockery\LegacyMockInterface|Mockery\MockInterface */
private $mediaRepository;
```

**Typed Properties Style (PHP 8.0+):**
```php
private Media $media;
private MediaRepositoryInterface|Mockery\LegacyMockInterface|Mockery\MockInterface $mediaRepository;
private MediaController $controller;
private $testStorage; // Mixed types still need no declaration
```

### **Class Constants for Test Data:**
Define reusable test constants at the class level:

```php
final class MediaControllerTest extends TestCase
{
    private const MEDIA_ID = 1;
    private const DIMENSIONS = '400x300';
    private const DEFAULT_FILENAME = 'test.jpg';
    
    // Properties follow...
}
```

## 3️⃣ Test Structure & Organization

### **Arrange-Act-Assert Pattern:**
- **Arrange**: Use `setUp()` or fixtures to prepare environment
- **Act**: Call the method being tested with controlled inputs  
- **Assert**: Check the outputs, side effects, or exceptions
- **Teardown**: Clean up mocks, fakes, or temporary files if needed

### **Optimized setUp() Pattern:**
Keep setup minimal and focused on essential dependencies:

```php
protected function setUp(): void
{
    parent::setUp();

    // Fake external dependencies
    $this->testStorage = Storage::fake('s3_media_cache');
    config(['image.disk' => 's3_media_cache']);

    // Create test data
    $this->media = Media::factory()->create();

    // Mock dependencies with essential expectations
    $this->baseConfig = $this->mock(SelectedBaseConfig::class);
    $this->baseConfig->shouldReceive('getAttribute')->with('id')->andReturn(self::MEDIA_ID);
    $this->baseConfig->shouldReceive('setAttribute')->andReturnSelf();
    $this->baseConfig->id = self::MEDIA_ID;

    // Instantiate system under test
    $this->controller = new MediaController($this->baseConfig, $this->mediaRepository, $this->mediaService);
}
```

### **Clean tearDown():**
```php
protected function tearDown(): void
{
    Mockery::close();
    parent::tearDown();
}
```

## 5️⃣ Mocking & Fakes

- Use mocking frameworks (PHPUnit Mock, Mockery) to isolate dependencies
- Use in-memory or fake storage when possible instead of hitting real external services
- Prefer Laravel's built-in fakes when available

**Example for Laravel:**
```php
Storage::fake('s3');
$this->mock(SomeService::class)
    ->shouldReceive('doSomething')
    ->once()
    ->andReturn('mocked');
```

## 6️⃣ Best Practices for Clean Code in Unit Tests

### **Core Principles:**
- **Avoid long tests**: Split into smaller focused tests
- **Single responsibility per test**: Test one behavior at a time
- **No external dependencies**: Tests should run offline and be deterministic
- **Readable assertions**: Use descriptive assertion messages if needed
- **Reuse setup code**: Use helpers or `setUp()` for repeated initialization

### **Advanced Patterns for Professional Unit Tests:**

#### **🔧 Helper Methods for Repetitive Operations**
Create private helper methods to reduce code duplication and improve readability:

```php
private function callPrivate(string $method, array $args = [])
{
    $ref = new \ReflectionMethod($this->controller, $method);
    $ref->setAccessible(true);
    return $ref->invoke($this->controller, ...$args);
}
```

#### **📊 Data Providers for Multiple Test Cases** 
Use static data providers to test multiple scenarios efficiently:

```php
/**
 * @test
 * @dataProvider formatProvider
 */
public function it_extracts_format_correctly(string $filename, ?string $requested, string $expected): void
{
    $this->assertSame($expected, $this->callPrivate('extractFormatFromUrl', [$filename, $requested]));
}

public static function formatProvider(): array
{
    return [
        ['image.jpg', null, 'jpeg'],
        ['image.png', null, 'png'],
        ['image.webp', null, 'webp'],
        ['image.unknown', null, 'png'],
        ['image.jpg', 'webp', 'webp'],
    ];
}
```

#### **🎯 Constants for Test Data**
Use class constants for reusable test values:

```php
private const MEDIA_ID = 1;
private const DIMENSIONS = '400x300';
```

#### **🔄 Efficient Loop Testing for Similar Operations**
When testing multiple similar operations, use loops instead of separate test methods:

```php
/** @test */
public function it_returns_404_for_missing_images(): void
{
    $request = new Request();
    $methods = [
        ['getImage', [$request, 1, 400, 300, 'missing.jpg']],
        ['getImageByType', [$request, 1, 'original', 'missing.jpg']],
        ['getImageById', [$request, 999]],
        ['getWysiwygImage', [$request, '../../../etc/passwd']],
    ];

    foreach ($methods as [$method, $args]) {
        $resp = $this->controller->$method(...$args);
        $this->assertInstanceOf(Response::class, $resp);
        $this->assertSame(404, $resp->getStatusCode());
    }
}
```

#### **🧪 Conditional Test Data Setup**
Use conditional setup in data providers for flexible test scenarios:

```php
/**
 * @test
 * @dataProvider placeholderProvider
 */
public function it_handles_placeholders_correctly(?string $existingFile, string $requestedExt, bool $expectsClosure): void
{
    if ($existingFile) {
        $this->testStorage->put($existingFile, 'test-data');
    }

    $result = $this->callPrivate('loadPlaceholder', [self::MEDIA_ID, self::DIMENSIONS, $requestedExt]);

    if ($expectsClosure) {
        $this->assertInstanceOf(\Closure::class, $result);
    } else {
        $this->assertFalse($result);
    }
}
```

## 7️⃣ Edge Cases and Exception Testing

Always include tests for:
- Invalid input
- Null values
- Empty collections
- Exceptions / error handling

**Example in PHPUnit:**
```php
$this->expectException(InvalidArgumentException::class);
$service->process(null);

## 9️⃣ Laravel-Specific Testing Patterns

### Feature Tests
- Test complete user workflows
- Use `RefreshDatabase` trait when needed
- Test HTTP responses, status codes, and JSON structure

### Unit Tests
- Test individual classes and methods in isolation
- Mock dependencies to focus on the unit under test
- Test business logic, services, and helper classes

### Common Laravel Test Patterns
```php
// Database testing
use RefreshDatabase;

// HTTP testing
$response = $this->postJson('/api/endpoint', $data);
$response->assertStatus(201)
    ->assertJsonStructure(['data' => ['id', 'name']]);

// Authentication testing
$user = User::factory()->create();
$this->actingAs($user);

// HTTP client testing
Http::fake([
    'api.example.com/*' => Http::response(['data' => 'mocked'], 200),
    'external-service.com/*' => Http::response([], 404),
]);

// Queue testing
Queue::fake();
// ... trigger job
Queue::assertPushed(SomeJob::class);

// Event testing
Event::fake();
// ... trigger event
Event::assertDispatched(SomeEvent::class);
```

## 1️⃣1️⃣ Assertion Best Practices

- Use specific assertions over generic ones
- Prefer `assertSame()` over `assertEquals()` for strict comparison
- Use collection assertions for arrays and collections
- Test both positive and negative cases

**Examples:**
```php
// Prefer specific assertions
$this->assertSame('expected', $actual);
$this->assertTrue($condition);
$this->assertCount(3, $collection);

// Collection testing
$this->assertDatabaseHas('users', ['email' => 'test@example.com']);
$this->assertDatabaseMissing('users', ['email' => 'deleted@example.com']);
```

## 1️⃣3️⃣ Professional Unit Test Characteristics

### **What Makes an Excellent Unit Test:**

#### **🎯 Focused & Efficient:**
```php
/** @test */
public function it_handles_svg_and_gif_files(): void
{
    $this->testStorage->put('1/svg/test.svg', '<svg></svg>');
    $this->testStorage->put('1/gif/test.gif', 'gif-data');

    $request = new Request();

    $this->assertSame(200, $this->controller->getImageByType($request, 1, 'svg', 'test.svg')->getStatusCode());
    $this->assertSame(200, $this->controller->getImageByType($request, 1, 'gif', 'test.gif')->getStatusCode());
}
```

#### **📊 Data-Driven Testing:**
- Use data providers instead of repetitive test methods
- Test multiple scenarios with single test method
- Keep data providers static and well-organized

#### **🔧 Helper Methods:**
- Extract complex reflection operations into helper methods
- Reuse common assertion patterns
- Keep test methods clean and readable

#### **⚡ Performance Optimized:**
- Use loops for testing multiple similar scenarios
- Minimize object creation in tests
- Share setup data efficiently

### **Code Review and Refactoring Checklist:**

**After writing test code, always:**

- **Review for clarity**: Ensure test names and logic are self-explanatory
- **Refactor for maintainability**: Remove duplication, extract common setup
- **Validate test coverage**: Confirm all critical paths and edge cases are tested
- **Check performance**: Ensure tests run efficiently without unnecessary overhead
- **Verify independence**: Tests should not depend on each other's execution order

**Professional Unit Test Checklist:**
- ✅ Test methods follow naming conventions (`it_[condition]_[expectedOutcome]`)
- ✅ Proper use of Arrange-Act-Assert pattern
- ✅ Appropriate assertions for the behavior being tested
- ✅ Mocks and fakes are used correctly
- ✅ Tests are isolated and deterministic
- ✅ Edge cases and error conditions are covered
- ✅ **Helper methods reduce code duplication**
- ✅ **Data providers used for multiple test scenarios**
- ✅ **Constants defined for reusable test values**
- ✅ **Efficient loops used for testing similar operations**
- ✅ **Conditional test setup based on data provider parameters**
- ✅ **Clean, minimal setUp() and tearDown() methods**
